PROBLEM 1: Two-Pass Input and malloc()
======================================

  One frequently encounters the following situation when reading files
  - The file contains some data that is to be read into a dynamically
    allocated array
  - There is no indication of how much data is in the file

  C programs commonly use a *two-pass* input strategy to handle this
  situation
  1. Read through the file once to count items in the file, then allocate
     memory for an array of that size
  2. Back up to the beginning of the file and read data from the file
     into the array

  The provided program 'twopass.c' demonstrates this technique along
  with several other input / formatting techniques.

  Creates file object *fin. If error has occurred (resulting in fin having a null value), return the NULL value.

  - Counts all the doubles in the file
    double tmp;                                // temporary space to read one double
    int count = 0;                             // count number of doubles in file
    while (1) {                                // first input pass: infinite loop to count doubles
        int ret = fscanf(fin, "%lf", &tmp);    // try to read a double

Starts with a temporary space for a double "tmp" and a counter "count". In the infinite while loop, fscanf attempts to read a double. When successful, increments count. Once end of file reached, break out of while loop.

Allocates enough space for "count" amount of doubles.

  - Moves the file read position to the beginning of the file
    rewind(fin);

  - Closes the file when reading is complete
    fclose(fin);

Each line starts with its row number in square brackets. The following format tag %8.2f means the following argument is restricted to 8 characters in length with a 2 decimal point precision. The next format tag specifies a 10 character length number and 4 decimal points using E notation.

C
~
  Examine the body of the 'while' loop in the 'main()' function. When working
  with binary files, we use 'fread()' rather than 'fscanf()' to read in a
  string value. However, we need information about the string's length so we
  know how many bytes to read.

  How did we learn of the length of the string representing each item's name in
  the binary file? What two things does this length help us do?

The length of the string is stored somewhere in the binary file. fread reads in an int size entry from the file. This will be the length of the string that gets stored in name_len.

This value then gets used to determine how many chars to read in for the next fread statement for the name and is also used to determine where the end of the string array is to place the null terminator.
